# Open Universe — серверное ядро (Rust)

Реализация ядра единого шарда по плану проекта: детерминированная симуляция,
бинарный протокол, UDP-транспорт, пространственный индекс, tick loop, interest
management и генерация мира. Код собирается, покрыт тестами и запускается.

## Структура

```
server/
├─ Cargo.toml                  # workspace
└─ crates/
   ├─ protocol/                # бинарный протокол + varint-сжатие + framing
   ├─ sim/                     # детерминированная симуляция + генерация мира
   ├─ spatial/                 # пространственный индекс (uniform grid)
   ├─ net/                     # UDP-транспорт, сессии, batching
   ├─ shard/                   # шардирование по системам (consistent hashing)
   ├─ persist/                 # персистентность мира и экономики
   ├─ economy/                 # предметы, инвентарь, рынок, производство
   ├─ combat/                  # оружие, щиты, броня, территории
   ├─ render/                  # софтверный рендерер (трассировка лучей → PNG)
   ├─ server/                  # авторитетный tick loop + interest management
   └─ client/                  # клиент: предсказание, реконсиляция, интерполяция
```

## Запуск

```bash
cd server
cargo test --workspace                       # 97 тестов
cargo run -p ou-server                       # демо interest management и дельт
cargo run -p ou-client                       # демо предсказания и реконсиляции
cargo run -p ou-sim --bin ou-worldgen        # генерация звёздных систем
cargo run -p ou-shard --bin ou-shard-demo    # шардирование и миграции
cargo run -p ou-server --bin ou-persist-demo # сохранение и восстановление мира
cargo run -p ou-economy --bin ou-market-demo # рынок, стакан, сделки, цепочки
cargo run -p ou-combat --bin ou-combat-demo  # бой, щиты, броня, территории

# реальный UDP-обмен с персистентностью (два терминала):
cargo run -p ou-server --bin ou-netd -- 127.0.0.1:7777 10 ./world
cargo run -p ou-client --bin ou-netclient -- 127.0.0.1:7777 8
```

### Боевые системы (проверено)

```
=== Шанс попадания (1000 выстрелов) ===
  автопушка   дальность 1500:  97%  80%  62%  44%  31%

=== Дуэль: лазер (энергия) против рельсотрона (кинетика) ===
  тик  8: щит 164 ( 54%), броня 308 ( 77%)
  тик 27: щит   0 (  0%), броня   0 (  0%)  ← уничтожен
Победитель по урону: игрок 2 (рельсотрон)
```

Попадание и урон — чистые функции от позиции, времени и «зерна выстрела»:
никакого `rand`, поэтому бой воспроизводим и проверяем сервером (античит).

### Экономика и рынок (проверено)

```
=== Стакан руды ===
  продажи (от лучшей): [(25, 60), (28, 100), (30, 40)]
=== Покупатель берёт 100 руды по лимиту 30 ===
  сделка: продавец 2 → покупатель 9, 60 шт по 25 (итого 1500)
  сделка: продавец 3 → покупатель 9, 40 шт по 28 (итого 1120)
VWAP = 26 · Всего сделок в журнале: 2
```

Все расчёты — на целых числах (`u64`), поэтому экономика детерминирована так
же, как физика. Инварианты (кредиты и предметы сохраняются, приоритет цены и
времени) закреплены тестами.

### Персистентность (проверено)

Мир переживает перезапуск сервера:

```
=== ЗАПУСК 1 (новый мир) ===
мир пуст — начинаем новый
[выход] мир сохранён: 66 байт, тик 179

=== ЗАПУСК 2 (загрузка существующего мира) ===
мир загружен: 1 сущностей, тик 179
игрок 2 «pilot» вошёл (сущность 2)   # id не конфликтует с загруженным
[выход] мир сохранён: 106 байт, тик 477
```

Сервер сохраняет мир периодически (`AUTOSAVE_TICKS`) и на выходе; при старте
загружает последний снимок. Снимок пишется атомарно (tmp → rename) и проверяется
контрольной суммой; при повреждении восстанавливается из резервной копии.

### Шардирование (проверено)

```
=== Добавляем узел 3 (масштабирование) ===
Переехало зон: 5 из 8 (consistent hashing двигает минимум)
=== Полёт игрока через весь кластер ===
  x = 1406250 -> миграция с узла 1 на узел 2
  x = 1640625 -> миграция с узла 2 на узел 3
Всего миграций за полёт: 4 (узел назначения в конце: 3)
```

### Снапшот-интерполяция (клиент)

Клиент буферизует снимки и отрисовывает удалённые сущности с задержкой 2 тика
(≈66 мс), плавно смешивая два соседних снимка. Собственный корабль не
интерполируется — он предсказывается. Тесты проверяют, что движение монотонно
и нет «телепортов» между снимками.

### Сжатие дельт (varint)

Снапшоты кодируются varint (LEB128) + zigzag для знаковых: мелкие координаты
занимают 1–3 байта вместо 4. Тест `compact_snapshot_is_smaller_and_roundtrips`
сверяет размер с «широкой» схемой и проверяет round-trip.

### Реальный UDP (проверено)

Сервер `ou-netd` за 5 секунд: **149 тиков** (ровно 30 Гц), **244 снапшота**,
2 клиента, средний исходящий трафик **≈202 байта/тик**. Клиент отправлял 119
кадров, реконсиляция давала максимальную коррекцию **0.006 у.е.** при ровном
соединении (то есть предсказание почти идеально) и 0.000 в идеальном случае.

### Генерация мира (детерминированная)

```
Bera-1      центр: звезда      | тел:  5 (планет 3, поясов 1) | ресурсов: 4736
Elar-4      центр: чёрная дыра | тел:  8 (планет 3, поясов 3) | ресурсов: 7831
...
Итого: 6 систем, 58 тел, 1 чёрная дыра
Повторная генерация идентична -> true
```

## Ключевые решения

### Детерминизм
Сервер и клиент вычисляют мир **бит-в-бит одинаково**:

- своя тригонометрия `det_sin`/`det_cos` (полином), без `libm`;
- только `+ - * /` и детерминированный `sqrt`;
- фиксированный `dt` (30 Гц), порядок перебора — `BTreeMap`;
- собственный ГПСЧ (SplitMix64) для генерации мира — воспроизводимо из семени;
- проверка через `World::checksum()` (FNV-1a).

### Квантование и floating origin
Позиция передаётся как `i32` с масштабом `10_000` (0.1 мм), ±214 км вокруг
локального начала. С floating origin этого хватает на локальную зону.

### Пространственный индекс
`ou-spatial` — равномерная сетка. Interest management обходит только ячейки,
пересекающие сферу запроса, а не весь мир. Результат всегда отсортирован по
`NetId` (детерминизм). Тест `matches_brute_force_on_random_layout` проверяет
эквивалентность наивному перебору на 500 телах и разных радиусах.

### Дельта-репликация и интерес
Сервер помнит последнее отправленное состояние каждого игрока и шлёт только
изменившиеся сущности; первый пакет — `baseline`. Пустая дельта + `ack` вне
зоны видимости — 29 байт.

### UDP-транспорт
`ou-net` добавляет поверх протокола: токен сессии (отсекает мусор и наивную
подмену адреса), очередь исходящих пакетов с батчингом (`flush`), отбрасывание
повреждённых дейтаграмм. Транспорт не влияет на детерминизм: привязка идёт к
номерам кадров и тиков, а не к порядку доставки.

## Тесты (97)

| Крейт | Что проверяет |
|---|---|
| `protocol` | квантование, round-trip сообщений, varint/zigzag, компактные снапшоты, framing |
| `sim` | тригонометрия, разгон, инерция, детерминизм, ГПСЧ, генерация систем, орбиты |
| `spatial` | поиск соседей, сортировка, перемещение, границы радиуса, сверка с перебором |
| `net` | пакет с токеном, отказ чужого/битого пакета, реальный UDP по loopback |
| `shard` | детерминизм владельца, равномерность, минимум переездов, миграции |
| `persist` | round-trip снимков мира и экономики, атомарность, восстановление из backup |
| `economy` | инвентарь, эскроу, приоритет цены/времени, сохранение кредитов и предметов, цепочки |
| `combat` | шанс попадания от дистанции, приоритет щита, типы урона, территории, детерминизм боя |
| `server` | видимость соседей, сокрытие далёких, пустая дельта, репликация движения |
| `client` | предсказание, реконсиляция, интерполяция (монотонность, границы, буфер) |
