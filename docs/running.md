# Как запустить Open Universe

Коротко: **два файла** — сервер и игра. Сначала `server.bat`, потом `game.bat`
в другом окне. Подробности ниже.

---

## Вариант 0. Два bat-файла (двойной клик)

В корне проекта лежат два файла:

| Файл | Что делает |
|---|---|
| **`server.bat`** | Запускает игровой сервер (мир). Работает, пока окно открыто |
| **`game.bat`** | Открывает графический клиент (Unreal Engine 5) |

**Порядок запуска:**

1. **Двойной клик по `server.bat`** — откроется окно с сервером:
   ```
   Open Universe - СЕРВЕР
   Адрес:   127.0.0.1:7777
   --> сервер запущен. Для игры откройте game.bat
   ```
   Не закрывайте это окно.

2. **Двойной клик по `game.bat`** — соберётся модуль (если нужно), создастся
   карта и откроется редактор Unreal.

3. В редакторе нажмите **Play** (или `Alt+P`) — корабль подключится к серверу.

Параметры (необязательно):

```
server.bat -Port 7800 -Seconds 600      # свой порт и время
server.bat -World world                 # мир сохраняется между запусками
game.bat -EngineRoot D:\UE_5.5          # если движок не найден сам
```

> Остановить сервер — `Ctrl+C` в его окне.

## Вариант 0б. Один запуск — оба окна

`play.bat` запускает сервер и сразу двух консольных игроков (без графики):

```
play.bat                                # двойной клик
play.bat -Players 3 -Seconds 30         # три игрока, 30 секунд
```

## Вариант 1. Одной командой (из папки игры)

```powershell
cd D:\Pro\open-universe
powershell -ExecutionPolicy Bypass -File tools\play.ps1
```

Важно: **сначала перейдите в папку игры** (`cd`), иначе скрипт не найдётся.
Скрипт сам определяет корень репозитория, поэтому `cd` нужен только чтобы путь
к файлу был верным.

Если запускаете из другой папки — укажите **полный путь**:

```powershell
powershell -ExecutionPolicy Bypass -File "D:\Pro\open-universe\tools\play.ps1"
```

Параметры:

```powershell
powershell -File tools\play.ps1 -Players 3 -Seconds 30      # три игрока, 30 секунд
powershell -File tools\play.ps1 -Port 7800 -World .\world   # свой порт, сохранение мира
powershell -File tools\play.ps1 -NoBuild                    # без пересборки
```

## Вариант 2. Вручную (два окна терминала)

### Шаг 1. Собрать

```powershell
cd server
cargo build --release
```

### Шаг 2. Запустить сервер (окно 1)

```powershell
cd server
cargo run -p ou-server --bin ou-netd -- 127.0.0.1:7777 60
```

Аргументы: `адрес:порт`, `секунды`, `[каталог мира]`.

Сервер печатает: токен сессии, частоту тиков (30 Гц), кто подключился.

### Шаг 3. Подключить игрока (окно 2)

```powershell
cd server
cargo run -p ou-client --bin ou-netclient -- 127.0.0.1:7777 50
```

Сколько окон — столько игроков. Каждый получит свой корабль.

## Посмотреть мир «глазами»

Сетевой рендер-клиент рисует то, что сервер отправил по сети:

```powershell
# окно 1: сервер
ou-netd.exe 127.0.0.1:7777 20

# окно 2: рендер (сохранит 4 кадра в render-net.png)
cargo run -p ou-render --release --bin ou-netrender -- 127.0.0.1:7777 8 4
```

ou-netd.exe 127.0.0.1:7801 60
ou-netclient.exe 127.0.0.1:7801 50

## Графический клиент (Unreal Engine 5)

Движок UE 5.5+ установлен, C++-модуль собирается и загружается. Одна команда —
и открывается редактор с настоящей 3D-сценой:

```powershell
powershell -ExecutionPolicy Bypass -File tools\build-client.ps1
```

Если при первом открытии проекта видно **чёрный экран** или редактор пишет
«Не удалось найти игровой модуль» — запустите сборку выше. Карта и сцена
(`/Game/Maps/OpenUniverse`) генерируются скриптом:

```powershell
powershell -File tools\make-map.ps1
```

Кроме того, `AOUGameMode` **сам достраивает** свет, небо, туман, планету и
менеджер начала координат при старте, даже если карта пустая — чёрного экрана
больше не будет. Подробности в `client/BUILDING.md`.

## Подключение UE5-клиента к Rust-серверу

Клиент говорит с тем же сервером `ou-netd` по тому же бинарному протоколу.

**Шаг 1. Запустите сервер** — двойной клик по `server.bat` (окно 1).

**Шаг 2. Откройте игру** — двойной клик по `game.bat`, затем **Play** (Alt+P).

То же самое из терминала:

```powershell
powershell -File tools\server.ps1          # окно 1: сервер
powershell -File tools\game.ps1            # окно 2: игра
```

Или одной командой (сервер + редактор сразу):

```powershell
powershell -File tools\connect.ps1
```

**Что происходит при подключении:**

1. Клиент шлёт `hello` на `127.0.0.1:7777` (токен сессии совпадает с сервером).
2. Сервер отвечает `welcome` со **своим** id сущности.
3. Клиент начинает слать ввод 30 раз в секунду и рисовать мир из снимков.
4. Чужие корабли появляются красноватыми — это другие игроки.

В логах это видно так:

```
LogOUClient: Приветствие отправлено на 127.0.0.1:7777
LogOUClient: Сервер принял: моя сущность = 3
```

```
ou-netd: игрок 3 «pilot» вошёл с 127.0.0.1:59738 (сущность 3)
```

**Управление (в режиме Play):**

| Клавиша | Действие |
|---|---|
| `W` / `S` | тяга вперёд / назад |
| `A` / `D` | рыскание влево / вправо |
| `↑` / `↓` | тангаж |
| `←` / `→` | рыскание |
| `Пробел` | огонь |
| `F` (зажать ~0,6 с) | выйти из корабля / снова сесть в него |

Когда игрок выходит из корабля (`F`), управление переходит персонажу:

| Клавиша | Действие |
|---|---|
| `W` / `S` / `A` / `D` | ходьба по поверхности планеты |
| `←` / `→` | поворот, `↑` / `↓` | взгляд вверх / вниз |
| `Пробел` | прыжок |
| `F` (зажать) рядом с кораблём | вернуться в кабину |

Персонаж ходит по **сферической** поверхности: «низ» направлен к центру
планеты, гравитация и привязка к рельефу — та же формула, что на сервере.

Движение клиент предсказывает сам (те же формулы, что на сервере), а сервер
исправляет расхождение — в логе видно `max correction` (обычно сантиметры).

Для автотестов клиент умеет сам подключиться и выйти из корабля:
`-OUAutoConnect -OUName=TestPilot -OUAutoExit`.

Собственный рендерер на Rust (`ou-render`) остаётся для тестов и кадров на сайте.
