# Команда и распределение ролей

Задача Фазы 0. На старте проект ведёт малая команда с широкими ролями; по мере
роста роли разделяются.

## 1. Текущее состояние

Проект разрабатывается как **открытый**: ядро на Rust, клиент на UE5, план и
релизы публичны. Уже есть работающие системы (182+ теста, 12 крейтов), поэтому
роли можно распределять по **уже существующим модулям**.

## 2. Роли на старте (минимальная команда)

| Роль | Ответственность | Текущие артефакты в репозитории |
|---|---|---|
| **Технический директор / архитектор** | ADR, выбор стека, границы модулей | `docs/adr-0001-engine.md`, `server/Cargo.toml` |
| **Серверный инженер (Rust)** | Симуляция, сеть, шардирование | `crates/sim`, `crates/net`, `crates/shard` |
| **Геймплей-инженер** | Экономика, бой, территории | `crates/economy`, `crates/combat` |
| **Клиентский инженер (C++/UE5)** | Рендер, ввод, floating origin | `client/Source/OpenUniverse` |
| **Технический художник** | Планеты, воксельная геометрия, атмосферы | `crates/render`, `crates/render/src/voxel.rs` |
| **DevOps** | CI/CD, релизы, инфраструктура | `.github/workflows/ci.yml`, `tools/release.ps1` |
| **Технический писатель / комьюнити** | Документация, сайт, отчёты | `docs/`, `index.html`, `report.html` |

Один человек может закрывать 2–3 роли на старте — это нормально для
предпродакшена.

## 3. Кого нанимать в первую очередь

1. **Серверный инженер (Rust)** — здесь ядро и главный риск.
2. **Клиентский инженер (C++/UE5)** — нужен, как только установят движок.
3. **Технический художник** — планеты и воксель должны выглядеть на уровне.

## 4. По мере роста (фазы 4–10)

| Направление | Роли |
|---|---|
| Контент | дизайнеры систем, левел-дизайнеры, нарративный дизайнер |
| Live-ops | продюсер, комьюнити-менеджер, поддержка, модерация |
| Качество | QA-инженеры, античит-аналитик, тестировщики нагрузки |
| Инфраструктура | SRE, специалист по базам данных, безопасник |
| Маркетинг | маркетолог, продюсер трейлеров, издательские связи |

## 5. Принципы работы

- **План — источник правды.** Задачи и статусы в `plan.md`/`plan.json`, сайт
  показывает прогресс автоматически.
- **Тесты обязательны.** Каждая система приходит с тестами (сейчас 192).
- **Релиз — рутина.** Версия выпускается одной командой или тегом; CI собирает
  и публикует автоматически.
- **Dокументация рядом с кодом.** Решения фиксируются в `docs/`, а не в чатах.
- **Открытость.** Внешние контрибьюторы могут брать задачи из плана.

## 6. Что уже автоматизировано (чтобы не тратить людей)

| Процесс | Инструмент |
|---|---|
| Сборка и тесты | GitHub Actions (каждый push) |
| Релизы и артефакты | тег → CI → GitHub Release |
| Сайт и прогресс | `data.js` + `app.js` (считается сам) |
| Отчёт о разработке | `report.html` |
| Симуляция баланса | `ou-market-sim`, `ou-landing-demo`, `ou-combat-demo` |
